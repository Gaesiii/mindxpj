# attendance - M05/M06 / Member 2

B07/B08/B12 implement manual attendance and uniform checks with current staff class scope, conditional versions, atomic logs and24-hour idempotency. No correction approval module is included. PM/member review and API_Gate remain pending.

`PATCH /api/v1/attendance/:id` requires Idempotency-Key and expected_version. Allowed fields are expected_version/status/arrived_at/absence_reason/reason. PRESENT requires a timezone-aware arrived_at on the session school_date, never in the future; a retrospective timestamp needs reason. Source MANUAL and verifier/time are assigned by the server. ABSENT accepts an optional absence_reason; arrival/source/uniform fields are cleared and uniform becomes NOT_APPLICABLE. Client UNMARKED reset and identity/source/verifier fields are rejected422. Manual recording atomically supersedes any still-PENDING scan. An already recorded attendance cannot be overwritten by a later scan.

`PATCH /api/v1/attendance/:id/uniform` requires Idempotency-Key, expected_version, observed_uniform and uniform_status, with optional reason/note. Only PRESENT can be checked. COMPLIANT must match the immutable required_uniform_snapshot. NON_COMPLIANT requires reason; OTHER requires note. UNKNOWN cannot be COMPLIANT. Payload reason/note map to uniform_reason/uniform_note. A new PRESENT starts NOT_CHECKED; presence does not imply compliance. Uniform checks assign checked_by/checked_at server-side.

CLOSED corrections require SUPERVISOR and reason, and append ChangeLog. GVCN receives409 SESSION_CLOSED. A successful same-key retry rechecks current authorization then returns the stored status/body before checking stale versions or CLOSED state. Reusing a key with another canonical payload returns409 IDEMPOTENCY_CONFLICT. Missing/invalid key or schema returns422. UUID IDs are distinct for Student, roster and Attendance.

Attendance responses include calculated arrival_status: PRESENT at or before snapshot late_cutoff_at is ON_TIME, after it is LATE; ABSENT/UNMARKED are NOT_APPLICABLE. Datetime responses are UTC with Z. No duplicated arrival state is stored. Versions start0 and increment once per successful attendance write, including combined QR/uniform confirmation. Failed validation creates no attendance change, log or idempotency record.

Tests: tests.test_attendance covers retry/conflict, current teacher scope, strict/future/naive/boundary timestamps, inclusive cutoff, closed corrections and rollback; tests.test_uniforms validates uniform combinations; tests.test_qr covers manual supersession and atomic combined confirmation. Run `.venv/Scripts/python.exe manage.py test tests.test_attendance tests.test_uniforms tests.test_qr tests.test_full_flow` with process DJANGO_SECRET_KEY in backend. SQLite busy returns409; retries should reuse the same key. No worker, queue or distributed lock is used.
